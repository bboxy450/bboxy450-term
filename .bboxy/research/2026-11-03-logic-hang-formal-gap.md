## Model verdict versus Rust enforcement

The new incident model is hand-written Rust building `bboxy450_tlc::Model`; it is not a `protocol!` declaration or a generated product reducer. Thus the experiment exercises the native checker and TLA+/Java parity path, and does not itself demonstrate shared macro-to-runtime derivation. The temporal protocol frontend was still unlanded when the model was assigned. A later protocol declaration could encode the finite phase/counter domains and fair occupied-work actions, but merely restating the model in macro syntax would not constrain an arbitrary effect backend.

`crates/bbt-yarn-macros/src/protocol.rs` — protocol! parses a closed finite grammar, rejects arbitrary calls/loops, and emits a pure reducer plus the symbolic model. `crates/bbt-yarn/src/protocol.rs:7-29` — effects are descriptions returned to ordinary Rust; they are not executed or bounded by the reducer. Merely mapping a hand-written worker file into a contract does not prove refinement.

A TLA transition has no implicit elapsed duration. To expose this bug, represent occupied recovery as multiple page-cost ticks while the owner cannot dispatch, with an explicit finite deadline counter. Ordinary eventual termination of finite recovery can pass despite missing a real deadline. The new LogicWorker* models at 954ce04e use H=4 pages, B=2 pending-request ticks, D=3 shutdown ticks, two FIFO slots, resumable cursor, saturated age/deadline and weak fairness only on the worker action group. Correct recovery returns after one page; broken recovery keeps the owner for H pages. The asserted prefix BeginProvenanceStep, RequestArrives, RequestShutdown, Tick, Tick, Tick reaches age=3/deadline=3. Safety and deadline-bound shutdown liveness have separate model pairs and negative controls. OS scheduling, syscall latency, growing history, arbitrary Rust and wall-clock bounds remain outside this finite abstraction. Oracle independently reran the repository's `formal.tools` and `formal.check_model(..., reuse=False)` for these eight registered cases in a separate private output directory: exit 0; four correct verdicts pass, broken recovery/audit controls fail with safety/liveness as prescribed; exact native/Java state and labeled-edge sets agree. Counts: core correct 295 states/397 edges, core broken 286/364; audit correct 2655/5933, audit broken 948/1765. Pinned Java/TLC artifacts were hash-validated by the canonical loader. Oracle evidence: `/var/folders/zd/mv_mr2d92p5_1r8yghzbs5vw0000gn/T/bboxy-oracle-hol-parity-ignlo4vq/oracle-results.json` plus per-model logs/graphs. This is eight-model verification using the canonical checker functions; the complete source-bound repository receipt under make test-formal remains pending.

The current tools can catch the modeled design before launching the product. They do not automatically reject an unbounded recover in arbitrary Rust effect code. Closing that link requires generating the actual scheduler/phase transitions from the same finite declaration, making page work/completion/yield/cancel explicit, and checking real implementation traces against those transitions. A sealed bounded-step API or dedicated effect owner can keep arbitrary work out of the request owner; a trait alone cannot prove that an arbitrary Rust callback returns promptly. Compile-fail fixtures can reject loops/arbitrary calls inside the declaration, but they do not prove the filesystem backend's duration. Keep a real process witness and a removed-guard failure; use stronger static/refinement tools only for the portions they actually cover.
