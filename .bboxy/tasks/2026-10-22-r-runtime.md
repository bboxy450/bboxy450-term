## R1 — `bbt-rt` crate: runtime, wake, messages, commands

Allowed: `crates/bbt-rt/**`, root `Cargo.toml`, `Cargo.lock`, `clippy.toml`.
1. One tokio multi-thread runtime (2 workers), started once, `rt::handle()`; `rt::is_ui_thread()` / `rt::assert_not_ui_thread()` (UI thread registered at startup).
2. `Waker` trait the app implements with `EventLoopProxy`; coalesced dirty bits per source, wake only on 0→1 ([[runtime]] §3).
3. `UiMsg` bounded queue with a non-blocking `try_send`; latest-value slot type; bounded view ring that drops oldest.
4. `spawn_command(argv, cwd, env) -> TaskId`: tokio::process, stdout/stderr chunked to the view ring, `Exited{status}`, `cancel(TaskId)`.
5. `clippy.toml` `disallowed-methods` per §1, applied to bbt-ui-model, bbt-ui, bbt-render; existing violations listed, not fixed, in the run log.
Verify: `cargo test -p bbt-rt --locked`. Tests: a producer at 1M msgs/s never blocks; 10k dirty sets give ≤ 1 wake until drained; a command streaming 100 MB finishes with the view ring bounded; cancel kills the process group; `assert_not_ui_thread` panics on the UI thread.

## R3 — terminal data path

Parent R2, W2.1 ✔. Allowed: `crates/bbt-rt/**`, `crates/bbt-mux/**` (consumer side only), `crates/bboxy450-term/**`.
1. Parser pool, N = cores/2, seats sharded by id; each owns its `bbt_core::Term`.
2. Per-seat double buffer of damaged rows; UI reads with `try_lock`, falls back to last rows.
3. Supervisor PTY bytes → parser shard; the supervisor never parses.
Verify: 1000 seats of `yes` with 15 visible: the visible ones update and UI CPU p99 is logged. Real zsh in one seat: type, see echo.
