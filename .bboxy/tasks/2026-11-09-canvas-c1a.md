## Goal

Step **C1a** of [[canvas]]: a seat can create a canvas, draw on it, read it back (data and image) and list canvases, and the canvas survives an app restart with the same digest. No GUI in this step; the canvas tab and sidebar list are C1b. Builds directly on C0 ([[tasks/2026-11-09-canvas-c0]], commit `960a4e6f6`), which is accepted and waiting to land.

## Base

Work on top of C0: your branch must contain `960a4e6f649da1a04ccf470ac9798ba75fa7482f`. If your workspace is not already on it, `git cherry-pick` or rebase onto it; the Oracle lands C0 then C1a in order.

## Steps

1. **Store** (in `bboxy450-canvas`, pure IO, no mux types): per [[d1794274420276169-canvas-record-type]] and the spec's "Own on-disk format" row, a canvas is `.bboxy/canvases/<slug>.md` (frontmatter record: type `canvas`, title, swarm, tags, creator seat, task) plus `.bboxy/canvases/<slug>.log.jsonl`. Keep the record codec a separate small module from the log codec (Markdown is interim). Append is atomic per batch (write+fsync the batch lines; a torn last line on load is dropped and reported, never silently replayed). Load = parse record + replay log; digest must match across restart.
2. **Multi-writer rule** (C1 makes several writers possible): the store assigns `seq` on append, under one per-canvas lock held only for the append; callers never supply `seq`. A batch carries an author and an optional `expect_seq` (last seq the caller saw); a stale `expect_seq` is **not** a refusal for adds, it is recorded and the batch still appends (ops address stable ids). A `Change`/`Remove` of an id already removed is a recorded no-op, not an error, so late or duplicate batches converge. Duplicate batch delivery is deduped by a caller-supplied `batch_id` (the MCP `op_id`).
3. **Formal model (d365)**: a small TLA+/Yarn model of item 2 in the formal-contracts suite (follow how existing models are registered under `crates/bboxy450-term/tests/formal_contracts/` and `verification/contracts.toml`): two seats plus the operator, ≤3 batches, delayed, duplicated and reordered delivery, restart between appends. Safety: the replayed picture is a function of the appended log; no batch applied twice; every acknowledged batch survives restart. Broken control: drop the `batch_id` dedupe → duplicate apply must be caught. Update the `bboxy450-canvas` entry in `verification/coverage.toml` (no longer implementation-only for convergence).
4. **MCP tools** in a new `crates/bbt-mux/src/mcp/canvas.rs`, modelled on how `skills.rs` registers its family. Swarm-scoped, any seat in the swarm may create; drawing allowed for the creator seat and Oracle-class seats (spec ruling "by grant; default creator plus Oracle"; a grant mechanism is later, say so).
   - `canvas_open {title | number | id, tags?}` → creates or opens; returns id, number, slug, digest. (Showing it to the operator is C1b; return `shown: false`.)
   - `canvas_list {tag?, cursor?}` → title, number, tags, last change, last author; newest activity first; bounded page.
   - `canvas_draw {id, ops: [...], expect_seq?}` → appends; returns new seq and digest. Ops use element ids and meaning fields only; any colour/font/weight field is refused by schema. Enforce the element cap and a per-seat op-rate cap (named consts) with a refusal that says which cap.
   - `canvas_read {id, frame?, image?: bool}` → elements as structured data; with `image: true` also a PNG rendered through the C0 `bbt-ui` canvas module and `bboxy450-render` headless renderer (fit-to-content camera), returned the way other tools return images, or as a file path if the MCP layer has no image content type (say which).
5. **`ctl canvas`** open/list/draw/read as thin calls into the same functions (scripts and tests draw too).
6. **Skill**: `.bboxy/skills/canvas/SKILL.md` (Agent Skills format, short): when to use a canvas, draw in small batches, read your own image back and fix overlaps, never send colours.
7. **Tests** (names contain `canvas`): a scripted seat draws ten elements over three batches; process restart (new store instance on the same directory) gives the same digest and the canvas is in `canvas_list`; duplicate `batch_id` applies once; torn last line is dropped and reported; cap refusals name their cap; colour field refused.
