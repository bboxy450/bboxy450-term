## Goal

Ship step **C0** of [[canvas]] (read it first, especially "Operator additions" and the C0 row). Decision: [[d1794274420276169-canvas-record-type]]. Smallest thing that proves the foundation: a canvas is an op log; replay is the picture; the picture renders through our GPU kit at any zoom.

## Steps

1. **New crate `crates/bboxy450-canvas`** (package `bboxy450-canvas`, import `bboxy450_canvas`, workspace version, licence header like every source file, `publish` per suite norm). Pure Rust, no GPU, no `bbt-*` render deps; serde only.
   - Elements for C0: `Shape` (box, rounded, ellipse, diamond, cylinder, actor; label; optional kind), `Connector` (from/to element ids, optional label, arrowheads, dashed), `Text` (heading/paragraph/note), `Frame` (name, member ids). Each has a stable `ElementId` (string) and `tags: Vec<String>`. Geometry in **f64 world coordinates**. Meaning only: kind/emphasis/status, never colour, font or weight.
   - `Op` = `Add | Change | Remove | Tag` with `author` (seat string), `seq: u64`, `at` (unix ms). `Canvas::replay(&[Op]) -> Result<Canvas, ReplayError>` deterministic; refuses unknown ids and over-cap element counts with a named reason (cap a `const`, e.g. 10_000).
   - `Canvas::digest()` = sha256 over a canonical serialization (sorted by id). Use whatever sha256 crate the workspace already uses.
   - JSONL load/save of the log (one op per line), plus the record frontmatter struct (title, swarm, tags, creator, task). No file watching, no MCP, no sidebar: those are C1.
   - `Camera { center: [f64;2], zoom: f64 }`: `world_to_screen`, `screen_to_world`, `pan`, `zoom_at(factor, screen_point)`. No clamp except finiteness. Output to the renderer is **camera-relative f32**.
   - Semantic zoom rule as one pure function: given an element's on-screen size, return `Full | Collapsed | Culled` (text → bar, frame → title only, sub-pixel → culled). Thresholds are named consts.
2. **`bbt-ui` module `canvas`** turns `(&Canvas, &Camera, viewport, theme)` into `bbt-ui-model` draw-list prims (`Prim::Path/Rect/Text/Group/Clip`), house style from `TOKENS`/`STYLE`, light and dark. Reuse existing path/arrow drawing from `modules/document_modal/diagram.rs` where it fits rather than writing a second arrowhead. Cull off-viewport elements.
3. **Goldens**: a fixed fixture log (`crates/bboxy450-canvas/tests/fixtures/c0.log.jsonl`, ~12 elements: shapes of each kind, connectors incl. dashed, text, two frames, tags) rendered headless via `bboxy450-render`'s `render_to_rgba`/`HeadlessRenderer` to PNG goldens in light and dark. Follow the repo's existing golden-update convention (env var to rewrite); tests compare, never rewrite by default. Must run unattended.
4. **Tests that must exist** (names contain `canvas` so the verify filter catches the UI ones):
   - replay twice → identical digest; reordered/duplicated op → `ReplayError` or documented deterministic outcome (single writer in C0; say which).
   - camera round-trip world↔screen within tolerance at zoom 1e-9, 1, 1e9 and at center 1e12.
   - semantic zoom returns each of Full/Collapsed/Culled at known sizes.
   - golden light + dark match.
5. **Formal coverage (d365)**: add `[[crate]] name = "bboxy450-canvas"` to `verification/coverage.toml` with `status = "implementation-tests"` (or a contract model if you make one), honest scope: single-writer deterministic replay only; multi-writer convergence model is C1/C6. Include a broken control (e.g. replay that iterates a HashMap unsorted must change the digest test) and the check commands.
