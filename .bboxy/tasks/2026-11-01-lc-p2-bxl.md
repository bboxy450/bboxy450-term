Binding: bboxy450-harness `.bboxy/interfaces/lc-bxl.md` (#4961), with its §5 canonical CBOR per d7cc01e, and `.bboxy/specs/log-converter.md` (#4965) §3 invariants, §4 budgets, §5 models and §7 P2. Read them fully.

Build, exactly as lc-bxl specifies:
- an append-only segment of zstd frames, each carrying canonical-CBOR IR events and a header (format version, dictionary id);
- a writer that fsyncs each frame;
- an index sidecar replaced by atomic rename; it is never a trailing seek table rewritten in place;
- a reader;
- a tail-follow reader that handles a concurrent writer and a partial last frame;
- crash recovery that rebuilds the index by scanning frames and truncates a torn tail;
- seal and rotation, where a sealed segment may get a seekable table;
- carrying the `Decoded` form, so unknown keys survive.

Formal: the TLA+ model `LcAppendLog` covers the writer, rename, crash and tailing reader. Safety: a reader never observes a torn frame, the index never points past durable bytes, and recovery is idempotent. Add the three broken controls from spec §5, including (c) an in-place table rewrite that exposes mixed bytes. The model is checked by bboxy450-tlc with Java TLC parity in `make test`, and listed in the inventory. If our Rust TLC can't handle a construct, record a gap with a reproduction (d4949). Don't drop the model.

Tests:
- torn writes at every byte offset, with recovery;
- a tail reader racing a writer;
- the size budget, checked structurally;
- compatibility: an older reader on newer frames skips unknown parts;
- `zstd -d` on a sealed segment works where the spec says it must.
