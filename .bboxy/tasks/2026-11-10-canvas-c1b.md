## Goal

Step **C1b** of [[canvas]]: the operator sees canvases in the app. Completes C1 (the C1 check: a scripted seat draws ten elements; after an app restart the canvas has the same digest **and is in the list**). ## Steps

1. **Canvas tab.** A canvas opens as a tab like any other (and can sit in a split), hosting the C0 `bbt-ui` canvas module over the C0 `Camera`. Pan and zoom with the same native gestures the fullscreen diagram viewer already handles (`crates/bboxy450-term/src/app_overlays.rs` `diagram_gesture`: pinch, pan, double-tap smart zoom); reuse that input path rather than a second gesture handler. Zoom has **no clamp** beyond finiteness (spec "infinite zoom"); semantic zoom collapses and culls as in C0. A "zoom to fit" key. Tab title is the canvas title.
2. **Live refresh, no animation.** When the canvas log changes (any writer: MCP, `ctl canvas`, another app instance), the open tab redraws from the store within one frame of noticing. Detect change without polling the disk every frame (e.g. the store/mux notifies on append; a cheap mtime/len check on focus is acceptable as fallback; say which). Animated reveal, pen mark, follow-pen are C2: not here.
3. **Sidebar canvases section** per swarm (spec ruling), newest activity first: title, last change, last author, at most three tag chips (spec "not overwhelmed"). Click opens the tab. Collapsible like the existing sections; empty swarm shows no section, not an empty box.
4. **`canvas_open` shows it.** From an MCP call the canvas opens beside the calling seat (split or adjacent tab; your choice, say which) and returns `shown: true`. If the UI is detached, return `shown: false` with the reason; never block the tool on the UI.
5. **Tests (names contain `canvas`), unattended, via `ctl`/headless captures only, never OS input:** scripted seat draws ten elements in three batches → app restart → same digest and the canvas row is present in the sidebar model; `canvas_open` from a seat returns `shown: true` and the layout has a canvas tab; zoom in by 1e9 and out by 1e-9 through the camera API keeps rendering without NaN; sidebar row shows ≤3 tags for a canvas with five. Add a headless capture of the tab to the report.
