# C1 memory: enforce owned storage, measure opaque overhead

Supersedes the universal allocation guarantee in [[decisions/d93377961364572-dream-c1-heap-allocation]]. Root's choice under [[tasks/2026-11-05-dream-c1-enforceable-memory-contract]]: retain **parent 32 MiB / child 96 MiB**, including each owner's protected **2 MiB control share**, but distinguish enforceable application storage from observed heap. There is **no supported absolute all-times native/whole-process 128 MiB guarantee** here. No wire/schema/version, input/output, worker-count, CPU/duty/latency, closure or settlement limit is increased.

The alternatives were to continue an unsupported universal allocation proof, widen the budget, or correct its guarantee domain. Choose the third: pthread/runtime startup and infallible serde Content/escaping/BTree internals are not covered by a Rust credit ledger. Absence of an arbitrary allocator proof is not a reason to reject every otherwise supported C1 job.

## Fixed shares and guarantee domain

| Owner | Allocation/admission and unchanged regression ceiling |
|---|---|
| Parent | 32 MiB: 2 MiB preprovisioned protected control, 8 MiB reserved helper-overlap allowance, at most 22 MiB other declared working storage. Observed attributed live working heap including attributable helper overhead must remain ≤32 MiB in the memory gate. Unrelated host heap is excluded, not C1 helpers. |
| Child | 96 MiB: 2 MiB preprovisioned protected control, 16 MiB reserved helper/startup-overlap allowance, at most 78 MiB other declared working storage. Observed full child heap, including startup/runtime/native heap, must remain ≤96 MiB in the memory gate. |
| Combined | Declared credits ≤128 MiB/job, without borrowing; sampled corresponding heap sum ≤128 MiB in the gate. These are respectively a credit invariant and an observed regression criterion, not a proof of every allocation between samples. Four jobs cannot bypass their individual admission/reserves. |

**Mechanically enforced domain:** C1-requested source/copy/read/line/frame buffers; owned context/manifest/record/page/index/canonical-byte buffers; retained parser/IR/D0 state payloads, strings and declared container entries; explicit queues and helper messages. Charge requested capacities and retained typed entry/payload sizes (with a documented accounting definition), not merely logical lengths; include old+new buffers during controllable growth/clone/serialization. Acquire nonblocking credits before creation/growth, use checked arithmetic and fallible reserve/build operations where C1 controls them, retain charges through drop and cross-thread transfer. Preflight known retained tree/container counts before growth. A bounded retained tree is in this domain; serde's hidden temporary Content/escape buffers, allocator rounding and internal BTree nodes are listed helper overhead, not falsely charged as exact native bytes. An estimate-only high-water counter does not implement admission. All helpers working for a job share that job's credits; retained job/control data stay bounded after execution.

**Measured/implementation-only domain:** opaque serde/container/regex/SQLite temporary allocations, native thread/runtime/allocator bookkeeping and fragmentation. The 8/16 MiB allowances are conservative engineering headroom inside 32/96, **not** proven bytes-per-input multipliers or allocator caps. Parent allowance covers one source/result parse/canonicalization unit plus at most two job-owned SQLite connections (run owner/checkpoint), streamed one bounded row/query at a time; configure bounded connection caches (≤1 MiB each, advisory for SQLite native total), fixed SQL, one ≤16 KiB retained record/row at a time and no whole-table materialization. SQLite hard_heap_limit is process-global and lookaside is not a per-connection total cap: do not change host-global SQLite/allocator limits. Child allowance covers one source parse/D0/serialization unit, fixed regex masks initialized once, and minimal startup. Retain raw+decoded+canonical+escape/growth overlap explicitly in each witness; release previous unit temporaries before the next. If measurements disprove headroom, reduce overlap/retention or improve that local implementation, never raise the ceiling or claim coverage by renaming it. Helpers may run normally under these tested assumptions; a universal native proof is not a default requirement.

## Practical preflight and owners

Keep existing caps: 64 KiB IO chunks; 256 KiB source line/manifest/frame; 32 sources; 64 MiB selected source+blob bytes; 65,536 envelopes; 1,024 blob refs; 4,096 output rows, 32 fingerprints/row, 8 KiB/row, 16 KiB/128 rows/page and 16 MiB total output. Add C1 resource preflight before general JSON materialization: maximum 32 nested containers, 4,096 members/elements in one container and 65,536 total values plus object keys per bounded document. Strings retain existing schema limits, otherwise are bounded by that document's byte cap. Fixed WorkerIn is flat with ≤10 fields and its existing scalar/string bounds; reject arrays/nested objects there before tagged serde buffering. These are finite resource limits, not changes to canonical IR or a memory-proof factor. Over-cap structure returns resource_limit; malformed/unsupported semantics retain existing errors. Bound retained state by admitted envelope/row/ref counts and credits; do not retain source trees across units or enumerate a corpus. Canonical serializer output is bounded/fallible where controllable, with one active output page.

Bound owner creation: ≤4 jobs/account, ≤2/root; per active job ≤3 dedicated parent owners (process/control, snapshot/validation and authority monitor), child direct C1 path main/control + one compute owner (≤2). Keep existing ≤4 short control requests/account and ≤1 capability probe/account; no per-record/helper thread multiplication. Existing per-seat source observation has bounded buffers and must be included in attribution when serving the job, not counted as free work. Use the already implemented minimal child dispatch; extra general async runtime startup is not the default. Native thread metadata, stacks and mappings are recorded separately. No general custom allocator or OS-limit project is required.

The 2 MiB control shares are provisioned before expensive work as bounded frame/status/cancel/error/settlement storage. Expensive paths cannot consume them. Controllable reservation/growth failure returns resource_limit and stops expensive admissions; controls continue, partial output never becomes completed. Child opaque allocation failure/exit is reported honestly and reaped or quarantined; infallible native calls may still terminate that private child. No shared-host abort, process-global allocator switch or kill is an admission strategy. Ordinary fallible/native errors preserve existing storage/resource/worker-lost semantics. No claim that reserves guarantee survival of arbitrary system OOM.

## Evidence and model limits

Keep actual parent+child multi-MiB, per-side overflow, four-job and independent control/cancel tests under make test-dream-c1; no heap/CPU test skip. Include dense/deep JSON, escapes, retained state, regex first-use and SQLite/checkpoint overlap. Observe parent attributed live storage/helper heap and child full heap high-water, credits and cumulative allocation **separately**; record attribution method, unsupported/unsampled paths, startup baseline and sampling coverage. Cumulative allocated bytes are not concurrent live bytes. Native overhead and stacks/mappings/file cache/RSS are not interchangeable heap measures. Any observed 32/96 or combined 128 MiB breach fails the relevant gate; it is not legalized as overhead. max(parent)+max(child) is a conservative bound on the corresponding observed peaks, not a measured synchronized peak; synchronized samples also do not prove all-times behavior.

The causal missing-reservation control must violate/detect the **declared working-storage** gate. Formal credit model proves only reserved work/control accounting and ownership, with a broken reserve-bypass control. List opaque allocations, platform/runtime assumptions and unsampled transient peaks as unmodeled implementation coverage. Never report model credit bounds as arbitrary Rust/native correctness. Existing latency/foreground/source/CPU/duty/settlement gates remain unchanged.

## Public authority fence; no Dream credential access

C1 is inspection, not a signing/custody check. Replace C Authority::capture's keys.signing_hold route (registry/dream_c1.rs:397-399 → identity/chain.rs:204-220, including custody.load at :212) with an immutable **host-authenticated public admission fence**. Do not substitute identity.status/admission: status.rs:237-252 decorates through the same custody-sensitive path. No Dream path calls private-key load, signing availability, Keychain/GPG, activation/unlock or a synthetic ready flag.

The existing identity runtime publishes the fence only from a completed authenticated host admission or successful public-proof verification. Add a narrow proposed public accessor/publisher in identity/status.rs and a custody-free verifier wrapper around chain.rs::device_current(:134-155). It may read/verify bounded public AccountHead/root/DeviceGrant/seat-grant data and expiry on the isolated authority owner; it never calls signing_hold/device_key/custody. This is necessary source glue for Rook if those files are outside the consumer's current brief, not authorization for a general identity rewrite. Existing status::observed_status alone and ready_issuer alone are insufficient authority.

Fence contents are internal host state, **no wire change**: daemon incarnation and monotonic fence revision; authenticated account/device/issuer identity and epochs, public-head/proof digest, grant/expiry/revocation status; seat/generation/grant-policy revision; routing/root/provider incarnations. Reuse logic.rs:3147-3154,6207-6252 provenance bindings and registry/routing.rs:62-68 epoch invalidation for route selection, not as a replacement for public identity verification. Identity admission/cutover/hold/revocation/expiry owners invalidate their fence before accepting subsequent C1 work; seat/grant/mute/root/provider writers invalidate matching job fences on committed revision changes. Refresh succeeds only from current authenticated public facts. Any external public-head/store change is detected by a bounded public revision/digest check before admission, at work-boundary authority monitoring and before final presentation; an unavailable/oversized check fails closed without blocking unrelated controls. Include expiry timers; no TTL-only stale-ready permission.

C1 captures the published fence after admitted seat/operator routing. Missing/stale fence means no expensive admission (existing stale_context error for unavailable public authority, or retained deferred work until a trusted refresh event); never fall back to credentials. The authority monitor compares monotonic incarnations/revocations and requests cancellation on change; settlement retains its owner. Final completed/status-page exposure revalidates the current public fence and exact captured context. A→B→A labels cannot revive the old revision. Bounded public SQLite reads/verification are permitted off owner under the measured native-overhead rules; general identity persistence is not required to become native-free.

Witness the real MCP/ctl route with a private admitted identity and custody/signing methods that fail/count calls: C1 Inspect/Status/Cancel perform zero such calls, including native-custody configuration; no operator prompt. Revoke/cut over/mute/replace root during work and before page presentation, including A→B→A, and assert no next expensive unit/new authority/stale page and honest settlement. Missing/stale public admission remains unavailable, never a fabricated identity. Keep controls independently responsive. A broken self-asserted/stale fence must fail the authority witness/model; public verification coverage and native/crypto overhead stay implementation evidence.
