## No free attachment interval; execution is ordinary work

Creation runs only on the existing isolated proof owner. Prepare/validate/reserve command, pipes, arguments and effect identity in ordinary1ms units; bracket only the prepared native creation call. On macOS use posix_spawn START_SUSPENDED with SETPGROUP (or a demonstrated equivalent): install PID/start identity/PGID, initial stopped state, controller custody and low priority before any helper user code runs. Apple XNU's public header defines both flags and kern_exec.c:2068-2079 stops the new task before execution. This is a supported direction, not a measured implementation. A post-spawn SIGSTOP does not meet it. Command::pre_exec(SIGSTOP) with a parent waiting for exec acknowledgement is not an acceptable substitute. No shared reactor performs launch.

Helper lifetime receives **no native exemption**. Reuse the one controller and a mutually exclusive job work grant: while the group runs, main proof/hash/parser work is parked; only bounded charged pipe/control work proceeds. At most two runnable helper owners. Initial grant target≤250us wall; request group stop before its conservative aggregate work charge can exceed1ms. Charge at least n*full runnable wall (n=2 for signature Git,1 otherwise), including stop delivery/confirmation delay, plus attributable controller/pipe CPU; this upper-bound charge is separate from measured helper CPU. Confirm stopped/exited state of all admitted members before paying stopped rest or issuing another work grant. A signal-send return is not stop confirmation. A helper blocked in IO still spends the conservative grant; IO/idle cannot bank future CPU. If the full grant charge exceeds1ms, fail the ordinary-work gate, stop/settle, and retain the measured excess; do not reclassify it native. Late OS control is a measured failure, not an all-times preemption promise.

After every expensive caller or group grant pay rest debt≥9*max(1ms,C), where C includes the full attributed charge for that span; creation uses its actual inclusive caller CPU, group grants the conservative charge above, and reconciliation may only add debt. Debt starts after work/confirmed stop, survives failures/restart/foreground changes, and cannot overlap another expensive span or be forgiven by helper IO. Independently service pause/status/cancel within existing hard latency/control gates; helper monitoring and any busy polling are measured job CPU, never a free lane. Foreground immediately revokes grants/stops the group; resume only after current activity revision, debt and authority checks. Native creation starts suspended, so foreground changes during that call do not release executable work.
