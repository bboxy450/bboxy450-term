## Closure, admission and one lifecycle

1. Consumer enables C1 only for the verified matching producer capability (otherwise C1 is disabled with runner_unavailable and the ordinary seat launch is preserved). It sets a new explicit --dream-owner term-c1 launch option for its managed bboxy harness seats. Producer retains that typed option through engine/ACP setup. In that mode, normal durable SessionClosed publication is the only notification; one DreamOwner gate must suppress both automatic legacy D0 replay/cache and automatic IR advice scanning. See [[decisions/d93377961364464-dream-c1-sole-post-close-owner]] for the managed-mode exclusion and large-blob close/foreground witness. The option selects ownership, never grants authority. All term-managed close hooks, including native-watch hooks, honor suppression; native EOF/import snapshots do not create a C1 job. Standalone/manual legacy replay is not silently rerouted or certified by C1.
2. Consumer's existing process-bound session observer records a bounded catalogue bookmark: seat/generation/session, repo binding, closed seq/raw-line digest and source file identity. Socket peer uid/PID/session binding is already checked by harness_log.rs:59-119; the log is owned/nofollow at :145-159. The unique SourceKey/run registration and retained close cursor advance are one per-seat journal transaction: crash before it replays the close, crash after it reuses the run. No directory/home discovery after close. A catalogue row without authoritative close stays ineligible. If C1-owned source notification was missed during daemon loss, recover only its retained per-seat cursor/bookmark, not an account corpus scan; unavailable proof stays unavailable.
3. With C1 close handling enabled for that managed seat, each authoritative close proposes one deterministic inspection. SourceKey and original operation records in the ICD coalesce duplicate close/restart/manual requests before hashing or launch. Capacity permitting, close admits exactly one job; before close, even idle/turn-ended sources admit zero. Capacity failure records Busy for that proposal, with no worker and no timer retry; a later explicit request can retry failed admission. Terminal successful runs are never replayed by duplicate close.
4. A manual Inspect selects 1..32 exact retained sessions of the caller's own seat. The public call returns admission/deferred/error promptly, not a completed scan. Host captures authority/root/provider epochs and only then snapshots sources. No source/KB/provider content is accessed on the live call owner.
5. Foreground priority is per owning seat, not “all seats idle”: observed new TurnQueued/TurnStarted sets foreground; observed TurnEnded/SessionClosed clears that turn, provided the stream is current and no other foreground turn is open. Unknown current foreground state defers expensive units. This can pause closed-source A while a new session B works; B's idle/TurnEnded never substitutes for A's missing closure. No inference/consolidation runs in an open producing source session.
6. Lifecycle: deferred → preparing → running ↔ paused → settling → completed/failed/cancelled. Cancel/deadline/context replacement stop new work, enter cancelling/settling, and retain the owner until compute and actual subprocess exit are observed. Cancellation/status controls remain independent of saturated progress/output. See restart semantics below.

C1 public-authority boundary ([[decisions/d93377961364581-dream-c1-enforceable-memory-contract]]): consume the existing authenticated host admission through a published immutable public-incarnation/revocation fence; do not call keys.signing_hold, credential custody, private-key/signing probes or identity.status/admission fallback. Host identity admission/public-proof verification publishes it; identity/grant/mute/root/provider owners invalidate it on actual revision/revocation/expiry changes. Reuse current routing/provenance fences and bounded off-owner current public-proof/digest checks; a weak ready cache is insufficient. Missing/stale public admission yields stale_context/no expensive work (retained deferred work waits only for a trusted refresh event), never credential fallback. Authority monitoring cancels on change and final presentation revalidates exact current epochs, preserving ABA. Necessary narrow identity/status.rs publisher and chain.rs custody-free device_current wrapper are explicit source glue for Rook if outside the consumer brief. No wire authority or general identity redesign is added.

The small behavioural addition to the accepted plan is close-event-driven deterministic C1 admission, required by the operator refinements; it is not a schedule/quota/inference runner.

## Isolated work, limits and responsiveness

Every job has a dedicated off-owner snapshot/validation worker and a separately owned harness subprocess with a dedicated compute/IO thread plus independent control handling. At most one expensive parent-or-child work unit runs for that job at a time. Never put source IO/hash/JSON/law checks, process spawning/wait/reap, file persistence or contended locks on UI, mux or shared async reactor owners. Framing on the reactor handles bounded bytes only; decoding/schema checks run off owner.

These finite caps close the accepted plan's unbounded-across-roots/thread-creation gap; four independent workers are not a single serial pool. |

A blocking syscall may outlive a cooperative unit; it occupies only that isolated owner, never a shared reactor. Stop unit admissions on foreground Activity immediately after the current bounded unit; persist counters/bookmarks and resume only that same captured run on a newer quiescent activity revision. Large sources are incremental/bounded; merely moving the current whole-corpus closure to spawn_blocking is insufficient.

Reuse the private native frame/input fixture for ≥240 frames with CPU p99 ≤4 ms and input-to-GPU ≤16.7 ms. Measure heap/RSS/thread CPU and unit overrun counts for a multi-MiB corpus and a bound-exceeding corpus; reject/label resource failure, never silently reduce corpus size. These are required future results, not measurements from this task.
