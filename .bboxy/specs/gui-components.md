# GUI components — model, layout, draw list, input, signals, lab

Owner: Vesper Greywind <ORACLE>. 2026-10-21. Status: DECIDED for W3.2 unless marked ASSUMED or **Gap**. Drafted from the lab at tag `ux-prototype-v2` (`lab/web/showcase.html`, `showcase.js`, `components.js`, `lab.css`), `design/bboxy-design-system.json` v10, `design/style.json`, `design/tokens.toml`, [[vision]] (Stack, Rendering and prototyping, Working rules), [[renderer]], [[ux-prototype]].

**Every `file:line` below is at tag `ux-prototype-v2`** (`git show ux-prototype-v2:lab/web/<file>`). HEAD has since moved the lab on (`16e5b22`: work-item statuses on task rows, epic groups in the stream dock, design system v11, ux-prototype §5.8); those additions are not modelled here and get their own pass.

Constraints fixed by the operator: raw wgpu, no toolkit; everything GPU-rendered; one design on macOS, Linux, mobile; `tokens.toml` + `style.json` are the single source and are included at compile time; one concern at a time; no premature optimisation.

Two crates carry this:

| Crate | Owns | Deps |
|---|---|---|
| `crates/bbt-ui-model` | element tree, state, events, layout solver, draw-list *types*, input routing, signal events, tokens | none beyond `std` (tokens generated by `build.rs`) |
| `crates/bbt-render/src/chrome/` | the chrome pass: turns a `DrawList` into GPU primitives; icon atlas; text runs via the text pipeline | `wgpu`, `bbt-ui-model` |

`bbt-app` owns winit, feeds pointer and key events into the model, hands the model's `DrawList` and `FxFrame` to `bbt-render`. `bboxybook` builds models from fixtures and renders through `headless.rs`. Neither the model nor the lab knows about a window.

The web lab mirrors the model on purpose: `components.js:2` declares "Mirrors the planned Rust ui-model: seat {key,name,harness,role,title,state}, tab {name,shortcut,tree}, space {name,key,tabs}". The Rust types below are that mirror, with vocabulary from [[vision]] (space → swarm, participants → shadows).

### 1.5 Tokens at compile time

`bbt-ui-model/build.rs` reads `design/tokens.toml` and `design/style.json` and writes `$OUT_DIR/tokens.rs`: `pub const TOKENS: Tokens = Tokens { color: ColorSet { dark: …, light: … }, density: [Density; 4], glow: Glow { … }, dim: Dim { … }, … }` and `pub const STYLE: Style = …`. No TOML or JSON parsing at runtime, no dependency in the shipped crate; the build script uses `toml` + `serde_json` as build-dependencies. A test asserts the generated constants equal `lab/web/tokens.js` (`window.TOKENS` and `window.STYLE`, written by `lab/web/gen-tokens.py:28-33`) so the two labs cannot drift. Theme and density are runtime indices into these constants; nothing else reads the files.

## 2. Layout

### 2.1 Decision: own engine, not `taffy`

**Own engine.** Lens: the operator's zen rule and the shape of the lab. Assumes: the layout stays what the lab draws. Breaks when: we need wrapping, grid, or intrinsic sizing from text.

Grounds:

- Everything the lab lays out is one of three things: a **row or column** of fixed, flex and fill children (`display:flex` everywhere: lab.css:74, :105, :121, :163; showcase.html:9-10, :81-82), a **binary split tree** with ratios (showcase.js:284-285 `A.style.flex = ratio; B.style.flex = 1 - ratio`), or an **overlay** centred at a fixed width (showcase.html:98,115). No wrapping, no grid, no `auto` margins beyond `margin-left:auto` (= one fill spacer).
- The split tree is not flex. `taffy` would model each split as a flex container with two children and a gap, and the divider's 8 px grab zone (showcase.html:87-88) as a third child or an overlay; we would write the tree walk anyway.
- The sidebar must virtualise at 1000 seats ([[vision]] target scale): only rows in the scroll window are laid out and drawn. A retained-tree flex engine lays out every node; a virtualised column is a loop over visible indices. Own code.
- `taffy` is ~15k lines of flexbox + grid (MIT, well maintained, used by Bevy and Dioxus). The engine below is ~300 lines. Pulling in the former to use a tenth of it is the kind of dependency the "no toolkit" decision exists to refuse.
- The one thing a flex engine does that we need is **intrinsic text width** for `flex: 0 1 auto` names (lab.css:166) and ellipsis. That is a text-measure callback either way; `taffy` would call it too.

The API below keeps `Size` and `Axis` as the only public shapes so that if wrapping or grid ever arrives, `taffy` can sit behind the same `solve_box` signature. Not planned.

### 2.2 The engine

```rust
pub enum Size { Fixed(f32), Flex(f32) /* weight */, Fill /* Flex(1.0) */, Text /* measured, shrinkable, ellipsis */ }
pub enum Axis { Row, Column }   // Row = horizontal main axis (lab `.split.v` is a Row of panes: showcase.html:82)
pub struct Box_ { axis: Axis, pad: Insets, gap: f32, children: Vec<(Size, Child)>, align: Align }
pub trait TextMeasure { fn width(&self, text: &str, style: &TextStyle) -> f32; }   // provided by bbt-render; the lab uses a monospace estimate
pub fn solve_box(b: &Box_, bounds: Rect, m: &dyn TextMeasure) -> Vec<Rect>;
```

`solve_box`: subtract padding and gaps, place `Fixed` children, measure `Text` children and shrink them proportionally when the sum overflows (ellipsis is the draw list's business, §3), divide the remainder among `Flex` weights. Cross axis: `Align::Center` for every row in the lab (`align-items:center`, lab.css:74).

Gutters and densities come from tokens, never literals: `layout.gutter` (2, alternative 4: showcase.js:9, :137), `layout.cohort_gap` (8, retired name kept), `density.*.row_h / tab_h / glyph / icon / font / font_small / pad_x / gap`. Density changes re-solve the whole tree (showcase.js:135,139). Compact hides the row title (lab.css:85).

Fixed heights from the lab that are constants in `STYLE`/`TOKENS`, not in code: title bar 38 (showcase.html:25; style.json has no entry: **Gap**, add `spacing.title_bar`), band 24 (showcase.html:42), strip 22 (`strip.height`), bumper 4/3, new-swarm button 40 (showcase.html:65), launcher panel 760 (showcase.html:115), launcher row 46 (`spacing.row_height_panel`).

### 2.3 The split tree

`solve_split(tree, bounds, gutter) -> Vec<(SeatId, Rect)> + Vec<Divider>`: for `Split { dir, ratio, a, b }` along `Row` (lab `v`) the first child gets `(w - gutter) * ratio`, the gutter sits between, the second gets the rest; `Column` likewise on height. Dividers are the gutter rects widened by 4 px each side for hit testing (showcase.html:87-88), drawn as nothing (design system elements.divider). Ratios clamp to 0.1..=0.9 (showcase.js:290). Drag-resize: on `Divider` press the model enters `Resizing { tab, path }`; every pointer move sets `ratio = (p - origin) / extent` along the axis and re-solves only the stage; on release it emits `SplitResized` and the mini-grid re-renders (showcase.js:288-293: "the mini-grid follows on re-render"). Panes have square corners and the glow paints over gutters without taking space ([[ux-prototype]] §2).

The same solver draws the **mini-grid** (components.js:169-183) at `sidebar.minigrid_w × minigrid_h` with a 1 px gap (lab.css:93) and the **banner** at 168×104 with a 3 px gap (showcase.html:101). One function, three scales.

### 2.4 Sidebar, narrow and phone

Desktop: the sidebar is a `Column` of `[Scroll(SwarmCards + NewSwarmButton), StreamDock]` at `Sidebar::width`, dragged at its right edge in an 8 px zone between 160 and 520 (showcase.js:341-346), persisted by the app. The stream dock caps at 38 % of the sidebar height (showcase.html:69).

The scroll body is **virtualised**: each swarm card's height is a pure function of its state (`band + rows × row_h + closed × tab_h + newseat + shadows × row_h + padding`), so the column computes offsets from counts, lays out only cards intersecting the viewport, and rows only inside those. Focus scrolls the row into view inside the sidebar, never the window (showcase.js:374-378).

Phone (`SheetState`): when the window's logical width is below **600 px** (ASSUMED; the lab shows the phone frame at 320 px, lab.css:147, and never names a breakpoint) the sidebar leaves the row and becomes a **bottom sheet** over the stage: full width, 62 % of the height, translated down to leave a 44 px handle, 320 ms on the one motion curve (lab.css:254-258). `SheetState { Closed, Open, Dragging(offset) }`; a drag on the handle moves it, release snaps to the nearer state. Rows switch to `Density::Touch` (design system foundations.density.touch = "phone"). The stage keeps the whole width; the launcher's 760 px panel becomes `min(760, 92vw)` as in the lab (showcase.html:100,115).

## 3. Draw list

### 3.1 Primitives

The chrome pass consumes one retained `DrawList` per frame. All coordinates in logical px with the scale factor applied once in the pass. Colours sRGB `[f32;4]`, premultiplied at upload.

```rust
pub enum Prim {
    Rect     { rect, radii: [f32;4], fill: Color, stroke: Option<(f32, Color)>, inner_highlight: Option<Color> },  // per-corner: band radius 4 inside a radius-12 card
    Hairline { from: Pt, to: Pt, color: Color },                                   // 1 physical px, style material.hairline_alpha 0.7
    Gloss    { rect, radius: f32, color: Color },                                  // band: 3-stop vertical gradient 88%→100%→82%, inset highlights: lab.css:548-549
    Text     { origin: Pt, text: Arc<str>, style: TextStyle, max_width: Option<f32> /* ellipsis */, color: Color },
    Icon     { rect, icon: IconId, color: Color },                                 // monochrome, currentColor: components.js:56-77
    Image    { rect, image: ImageId, radius: f32 },                                // the portrait, circle at 18 px: components.js:96
    Clip     { rect, radii: [f32;4] },  Unclip,
}
pub struct TextStyle { scale: TypeScale /* style.type: input, banner, title, subtitle, kind, body, row, section, badge, caption, band */, weight: u16, mono: bool, tracking_em: f32, uppercase: bool }
```

`IconTile` and `Badge` from §1.3 are not primitives: `IconTile` = `Rect{radius tile} + Icon`, `Badge` = `Rect{radius badge, tint} + Text{mono}`, `Pill` = `Rect{radius 999} + Text/Badge pairs + Hairline separators`, `StateGlyph` = `Text{mono}` plus a `Rect` ring (shim) or a dashed ring (inferred: four short `Hairline`s) plus the kind mark `Text` at 7 px. A `Shadow` (style `shadow.floating` / `shadow.pill`) is a `Rect` with a large blurred alpha falloff drawn by the same SDF shader as the glow: one parameter, no second pass.

### 3.2 Element → primitives

Every element implements `fn draw(&self, rect: Rect, ctx: &DrawCtx, out: &mut DrawList)` where `DrawCtx { theme, density, tokens: &TOKENS, style: &STYLE, dim: Option<Dim> }`. Colours and sizes are read from `ctx`; the element never holds a colour literal. Examples, lifted from the lab:

- **SwarmCard** (showcase.html:39-44, lab.css:542-560,612-615): `Rect{ radii [12;4], fill surface @ card_alpha 0.72, stroke hairline }`, bumper `Rect{ radii [0,0,12,12], fill swarm colour, h 4 or 3 }`, `Gloss{ band, radius 4 }`, band `Text{ band scale 10.5, weight 600, tracking .16em, uppercase, white 92% }`, count `Text{ 10.5, white 70% }`, `Swatch` = `Rect{ circle 10, fill swarm, stroke 1.5 white 85% }`. Shut: band only, roll-up glyphs worst-first max 6 (components.js:231-236), waiting badge (:238).
- **SeatRow** (components.js:149-167; showcase.html:47-56): optional `WhereMark` icon 12 → `IconTile` 16 radius 5 → name `Text{ row 12.5, weight 600, seat colour, ellipsis }` → `RoleMark` → `MutedMark` → title `Text{ font_small, fg_dim, ellipsis, Fill }` → right group: unread `Badge{ role colour }`, `Badge{ ⌘N mono }`, `StateGlyph`. Focused: `Rect{ radius 6, fill selection tint fg 9% }`; hover: fg 6 % (style `tint`). Never both a bar and a tint (ux-prototype §3.2 "no bar").
- **Strip** (components.js:300-311, lab.css:162-173): `Rect{ fill seat colour, h strip.height }`, `CloseDot` circle 12 `#FF5F57`, `WhereMark`, harness `Icon` 13 (tile-less), name, `RoleMark`, title with " · waiting for <kind>" when waiting, `Badge ⌘N` on black 22 %, `MuteToggle`, `StateGlyph` 11.

- **Launcher** (showcase.html:98-153): backdrop `Rect{ fill bg @ 0.35 }` full window; panel `Rect{ radius 20, fill surface @ 0.78, stroke hairline, inner_highlight white 8%, shadow floating }`; crumbs, input `Text{ input 22 }`, section labels `Text{ section 12, weight 500, fg_dim }`, rows 46 high with `IconTile` 30, label `Text{ title 16 }`, sub `Text{ subtitle 15, fg_dim }`, kind `Text{ kind 14 }`, number `Badge` 24×22 or `Chevron`; footer swatch, name `Text{ 14, 600 }`, reroll circle 28, `Pill`.

### 3.3 Dim, wash, material

**Dim is a colour transform at draw time, not a render pass.** `Dim { saturate: 0.10, opacity: 0.45, wash: 0.28 }` from `[dim]`: an unfocused pane or swarm card pushes `ctx.dim = Some(..)`; every colour an element reads passes through `ctx.color(c)` = desaturate to 10 %, multiply alpha by 0.45; grounds pass through `ctx.ground(c)` = mix 28 % toward `fg_dim` (lab.css:160-161, :629-631). Borders and bumpers bypass the transform so identity survives (ux-prototype §4.1, §3.1). No offscreen texture, no filter pass; the result is pixel-equivalent for flat colours, which is all the chrome has.

**Frosted material** (`panel_alpha 0.78 + 30 px blur + 1.4 saturate`, style.json) needs a blur of what lies beneath. v0.1 chrome draws the alpha and the hairline and skips the blur; the fx pass adds a blurred copy of the stage behind the launcher and the sidebar in W3.3 ([[renderer]] §1 lists "frosted sidebar" under `fx`). The parity report will show the difference; accepted for W3.2.

### 3.4 Damage and retention

- The element tree is retained in the model; a `dirty: bool` sits on `Window`, `Sidebar`, `Stage`, `Overlay`. Any `Input` or `Update` that changes state sets the flag of the subtree it touched.
- A frame is built only when some flag is set or the fx pass has a continuous animator on screen (active or waiting seat, live ripple, countdown). Idle window, idle seats: zero frames ([[renderer]] §1 "render on change").
- v0.1 rebuilds the **whole** `DrawList` when any flag is set and uploads it as one vertex buffer. At cozy density a 15-seat scene is ~400 primitives; a 1000-seat sidebar is virtualised to the visible ~40 rows, so the list never exceeds a few thousand. Per-element splicing of the buffer is a later optimisation that waits for a measured frame time ([[vision]] Working rules).
- Focus change touches only the focused and previously focused row and pane (showcase.js:352 "Focus change touches classes only: no re-render"): the model marks those two elements, the list rebuilds, nothing re-lays out. Rows never move on focus (design system principle 7).
- State change swaps the glyph and the stroke only (showcase.js:261-269 `setState`); layout untouched.

## 4. Input

### 4.1 Routing

`Model::input(&mut self, ev: Input) -> Vec<Event>` with

```rust
pub enum Input { Pointer(PointerEv), Key(KeyEv), Text(char), Wheel { at: Pt, dx, dy }, Resize { w, h, scale }, ThemeHint(Theme), Tick(Instant) }
pub enum PointerEv { Down { at, button, mods }, Move { at }, Up { at, button }, Leave }
```

Hit testing walks the last solved layout in reverse paint order: overlay first (the launcher backdrop swallows everything and closes on a click outside the panel, showcase.js:160), then stage dividers (their 8 px zones outrank panes), panes, title bar, sidebar handle, sidebar rows. Each hit yields a `Target` (`Row(seat)`, `Band(swarm)`, `Swatch`, `Divider`, `Pane(seat)`, `Strip(seat)`, `CloseDot`, `MuteToggle`, `NewSeat(swarm)`, `NewSwarm`, `Undo(seat)`, `ShadowRow`, `LauncherRow(i)`, `TitleBar(btn)`, …). A `Down` records `pressed: Option<(Target, Pt)>`; `Up` on the same target is a click. Phantom rows take clicks for the stream filter and nothing else (showcase.js:309).

### 4.2 Focus model

Two focuses, never blurred:

- **Keyboard focus** = `Stage::focused`. Set by click on a row or pane, by launch, by undo, and by the pane-navigation keys **⌘⌥ arrows** (spatial) and **⌘⌥ Tab / ⌘⌥⇧ Tab** (tree order). **Decision [[d26-terminal-key-ownership|#26]] (2026-10-23):** with a terminal pane focused, every plain key including Tab and arrows goes to the PTY; plain Tab, Shift+Tab and arrows navigate only in the launcher, overlays, text fields and app chrome. A terminal must never lose a keystroke to the chrome. Shown as focus brightness (selection tint on the row, full contrast on the pane, glow ×1.6). If the seat lives in another tab or swarm the stage switches; no swarm opens or shuts because of it (showcase.js:362-381, :93).
- **Dwell focus** on panes only: `Move` into a pane arms a 150 ms timer; `Tick` past it moves keyboard focus **without** `Locate` if the last key press is more than 1 s old (showcase.js:406-410). Rows never focus on hover; they only tint (:311).
- **Text focus**: at most one `TextField` (swarm rename, launcher query, settings search, purge name) holds `Input::Text`. While a field holds focus, plain arrows go to the field and pane navigation needs ⌘⌥ arrows (showcase.js:399-400); Enter commits, Escape cancels (components.js:225).

Arrow navigation (showcase.js:383-396): among pane rects, keep those strictly ahead in the direction, score `along + 2·across` from centre to centre, pick the minimum. Tab cycles the stage's leaves in tree order (showcase.js:562). Keyboard moves emit `Locate { Pane }`.

### 4.3 Drag and drop

One state machine on `Model::drag`:

```
Idle --Down on Row(seat) | Strip(seat)--> Pressed{seat, origin}
Pressed --Move > 6 px--> Dragging{seat, ghost at pointer+12, zone: None}      // showcase.js:323
Dragging --Move over Pane(other)--> zone = nearest edge of the four (left,right,top,bottom)   // zoneOf :320
Dragging --Up with zone--> Event::Place{seat, Split{target, side}}; Idle      // :335 → placeSeat 50/50, old split collapses :106
Dragging --Up without zone | Escape--> Idle
```

Phantoms are not drag sources (showcase.js:315). The divider and the sidebar edge use the same `Pressed → Resizing` shape without a ghost. The drop zone tints the hovered half with the selection tint (showcase.html:20-22); the preset launcher reuses the same half with the accent at 22 % breathing (showcase.html:134-135).

|---|---|---|---|---|

Native cursor intent (operator, 2026-10-28): enabled actionable controls and
links use the platform's pointing hand; editable text uses the text cursor;
inactive controls and blank areas use the default pointer. Resize handles retain
their directional resize cursor. Shared UI regions resolve this from the same
retained hit tests and clipping as clicks. The desktop host maps the intent via
winit on macOS, Windows, X11 and Wayland, with no platform-specific cursor assets.
Document/launcher overlays block underlying controls, active drags retain their
cursor, and movement, layout changes, pointer exit and focus loss refresh/reset it.

Sidebar conversation (operator, 2026-10-28): its two horizontal handles resize
navigation versus chat (`sidebar-conversation-resize`) and history versus draft
(`sidebar-composer-resize`). Both use the vertical resize cursor and the same
retained geometry for native and `ctl ui drag` input. Save requested
`[sidebar].conversation_fraction` (default 0.45) and optional
`composer_body_height` in host preferences on release; previews and persistence
never restart a harness or require a protocol change. Fit the saved requests to
short windows without overwriting them, keep panels nonnegative and address/send
controls visible, and scroll a bounded draft body with caret and hit coordinates
kept in that viewport. Overlay input and captured drag precedence still apply.

Chat presentation (same operator pass): Enter sends a focused draft, Shift+Enter
adds a line, address-picker Enter chooses its recipient, and repeated Enter or
IME preedit never sends extra messages. Send advertises ↵; the priority control
is a separate, plainly labelled control. Routine successful storage IDs and
projection-window bookkeeping do not occupy the conversation/draft; meaningful
pending, held, refused, partial or unknown outcomes stay visible, and original
records, receipt evidence and read coverage remain intact. Message surfaces have
clear author/body hierarchy and spacing, with repeated local issuer/role/default
priority/transport badges omitted. Chat timestamps use the machine's local time
zone and the timestamp's daylight-saving rules, retaining the raw UTC instant
for evidence; timezone discovery runs off the UI thread.

Rules the model enforces: `Locate` is emitted only from click and keyboard paths and after a stage switch once the new layout exists (showcase.js:367); `Update`s from the mux never emit it. On a light theme the fx pass multiplies toward the seat colour instead of adding (showcase.js:493-497); the model only supplies `theme` and `bg`. Waiting pulses at `motion.pulse_ms`, active breathes at `glow.active_pulse_ms`; both read `now_ms` so rows and panes share one clock (components.js:140-146).

## 2b. The component library (operator, 2026-10-21, from reading the parity diffs)

"We need our own wgpu-based component library: tables, blocks, divs, buttons that we can later style; style with shaders and sizing." The module code in bboxybook grew as hand-drawn compositions; the diffs show it. The fix is a generic layer between the draw list and the modules, the same way the lab's CSS sits between its HTML and the pixels.

**Crate `bbt-ui`** (new; ui-model keeps the pure model, bbt-ui owns components; renderer owns passes). Every component is retained, laid out by the engine in §2, draws into the §3 list, and is styled by a `Style` struct resolved from tokens plus overrides:

| Component | Props | Style surface |
|---|---|---|
| `Box` (the div) | children, direction row/column, size fixed/flex/fill, padding, gap, clip, scroll | background (solid, gradient, **material**: flat, gloss, frosted, glow), border width/colour, per-corner radius, shadow, dim, opacity |
| `Text` | runs, wrap, ellipsis, selectable | type scale step, weight, colour, tracking, mono/proportional |
| `Button` | label, icon, kind primary/ghost/danger, shortcut hint, enabled | all of Box + pressed/hover/focus materials |
| `Table` | columns (fixed/flex/fill), rows (virtualised), header, selection, sort | row height per density, zebra, hairlines, selection band |
| `List` | items (virtualised), selection, nested | row height, indent, selection band |
| `Input` | value, placeholder, prefix icon, validation | Box + caret/selection colours |
| `Chip`, `Badge`, `Pill`, `Glyph`, `Icon`, `Image`, `Hairline`, `Divider`, `Spinner`, `Checkerboard` | as in §3 atoms | tokens |
| `Stack`, `Spacer`, `ScrollView`, `Overlay`, `Modal` | layout and layering | material, blur radius |

**Styling.** `Style` is data: a tokens reference plus overrides, serialisable, so bboxybook can show a component across styles the way the lab shows states. Materials are shaders: `flat` (solid), `gloss` (the band's gradient and highlight), `frosted` (backdrop blur, [[renderer]] fx), `glow` (particle border, state-driven). A component picks a material by name; sizing comes from density tokens; nothing is drawn ad hoc inside a module. Modules (`SeatRow`, `SwarmCard`, `Launcher`, …) become compositions of these components only.

**Parity rule.** Each lab element maps to one component or composition; the lab's CSS class is the component's name in `bboxy-design-system.json`, so the diff for a seat row is the diff of `Box + Icon + Text + Glyph + Badge`, and a fix in `Box`'s hairline fixes every row at once.

Build: W3.2d after W3.2c, re-basing the existing modules onto the library with parity re-runs between steps; no module keeps hand-drawn primitives after it.

## 2c. The layer cake (operator, 2026-10-21: "we are building from scratch, so it is a layer cake of abstractions; we need more layers of granularity in the development process")
